# saddlepoint

An embeddable, Rust-native first-order solver for linear programs (QP and
conic problems later), built on restarted Halpern PDHG (the method used by
cuPDLPx). The same algorithm runs on the CPU and the GPU. You can use it
from Rust with no Python, Julia or server process, and C, Python and
`good_lp` bindings are planned.

> **Status: Phase 1 (CUDA backend).** The CPU and CUDA backends both work
> and take identical iterations on every bundled Netlib instance. GPU
> performance work (CUDA Graphs, a custom SpMV kernel) is Phase 2. Expect the
> API to change.

## Workspace

| Crate | Role |
|---|---|
| `saddlepoint-core` | Problem types, Ruiz / Pock-Chambolle scaling, the PDHG loop and termination checks. Generic over a small, fused `Backend` trait. |
| `saddlepoint-cpu` | Reference backend (rayon). Used as the source of truth in tests and as the fallback when there's no GPU. |
| `saddlepoint-cuda` | GPU backend in f64: cuSPARSE for SpMV, plus fused NVRTC kernels (`kernels.cu`) compiled at run time, so there's no nvcc step. CUDA libraries are loaded dynamically, so it builds without CUDA installed. Also holds `sp-bandwidth`. |
| `saddlepoint-io` | Free-format MPS reader. |
| `saddlepoint-check` | Independent KKT checker. It shares no code with the solver and validates every claimed solution in the tests. |
| `saddlepoint-cli` | The `saddlepoint` binary: solves an MPS file and checks the result. |

## Try it

```sh
cargo run --release -p saddlepoint-cli -- data/netlib/afiro.mps --tol 1e-8
cargo run --release -p saddlepoint-cli -- data/netlib/25fv47.mps --gpu      # needs an NVIDIA GPU
cargo run --release -p saddlepoint-cuda --bin sp-bandwidth                  # needs an NVIDIA GPU
cargo run --release -p saddlepoint-cuda --example speedup                   # GPU vs CPU per iteration
```

## Algorithm (current)

- Preconditioning: 12 geometric-mean passes, 10 Ruiz rounds, Pock-Chambolle
  (α = 1), then a scalar rescaling of bounds and objective.
- Step size η = 0.998 / ‖A‖₂, with ‖A‖₂ estimated by power iteration on the
  backend. τ = η/ω and σ = ηω.
- Iteration: reflected Halpern PDHG (ρ = 1).
- Restarts: sufficient (0.2), necessary (0.5) and artificial (0.36)
  criteria on the fixed-point residual in the PDHG metric, relative to its
  value at the epoch's anchor, checked every 64 iterations.
- Primal weight ω: starts at 1, and a PID controller (cuPDLPx gains) updates
  it at each restart. A safeguard falls back to the best-balanced weight.
- Termination: relative KKT tolerance, computed in the original (unscaled)
  space. Infeasibility is detected from the iterate difference since the last
  restart.

## Testing

```sh
cargo test --workspace --exclude saddlepoint-cuda      # unit + quick Netlib set
cargo test --release -p saddlepoint-cpu --test netlib -- --ignored   # slow Netlib set
cargo test --release -p saddlepoint-cuda                             # GPU vs CPU; skips without a GPU
```

The CUDA tests compare every `Backend` method with the CPU reference, then
solve Netlib on both backends. CI has no GPU, so it doesn't run them.

`data/netlib/reference.csv` holds HiGHS 1.15.1 objectives, generated by
`scripts/highs_reference.py`. At 1e-6, 16 of the 18 bundled instances pass
the KKT check and match HiGHS to a relative 1e-5. Two don't yet. Greenbea
reaches the 1M iteration limit (#1), as cuPDLPx also does at this
tolerance. Klein1's infeasibility isn't detected (#2).
